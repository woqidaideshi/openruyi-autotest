# 为145个基础软件包生成100%功能覆盖的测试用例

## 背景

之前已为 ~170 个基础软件包生成了存根测试（`gen_170.py`），并在服务器上安装了这些软件包（`install170.py`）。但这些存根测试仅覆盖：
- 软件包安装验证（`rpm -q`）
- 命令可用性检查（`which`）
- 版本/帮助信息（`--version`, `--help`）
- 基本错误处理（`--invalid`）

当前需要按照 `acl` 软件包的完整标准，将存根测试升级为 100% 功能覆盖的测试。

## 参考标准：acl 测试套

`acl` 测试套特点：
- 主脚本 `test.sh`：9313 字节，涵盖 11 个测试维度
- 11 个子测试目录，每个针对特定功能点
- 每个子测试有独立的 `main.fmf` 和 `test.sh`
- 测试维度：基本功能、高级功能、删除、递归、符号链接、chacl命令、继承、权限验证、错误处理、特殊场景

## 软件包分类

按功能类型大致分为：
1. **CLI 工具型**（有明确命令行工具）：如 sqlite, openssl, bzip2, rpm, gawk, diffutils, git 等
2. **库包型**（无 CLI，仅提供 .so 库）：如 libpng, popt, gdbm, libffi, libgcrypt 等
3. **构建工具型**：如 cmake, meson, ninja, autoconf, automake 等
4. **系统配置型**：如 setup, config, chkconfig, tzdata 等
5. **服务/守护进程型**：如 dbus, dbus-broker, unbound 等
6. **开发/测试工具型**：如 gdb, kyua, beakerlib, swig 等

## 目标

1. 对每个软件包，在服务器上深入学习其功能点（命令、参数、服务等）
2. 生成 100% 覆盖的测试脚本（参照 acl 标准）
3. 在服务器上逐一验证
4. 全部完成后批量运行，修复失败用例
5. 更新文档（README.md、coverage 详情等）
6. 提交代码并创建 MR

## 执行策略

**选择 A：批量自动生成**
- 从服务器自动收集每个包的命令/参数/服务信息
- 批量生成初版 100% 覆盖脚本
- 上传到服务器逐包验证修复
- 全部通过后统一运行确认

## 服务器验证流程

**选择 B：分批验证** — 先生成本地所有测试脚本，再分批上传服务器编译运行修复。

## 库包覆盖标准

**选择 A：深度测试** — 对纯库包编写 C 测试程序，链接 `.so` 库文件，调用核心 API 验证功能。测试程序编译并运行在服务器上。

## 排除项

- 已存在的完整测试套（如 acl）不重复生成
- bootstrap 变体（python-packaging:bootstrap 等）在对应目录中添加子测试

## 测试结构

**选择 A：子目录结构（同 acl）** — 每个包按功能点拆分多个子测试目录（如 `test_sqlite_basic/`, `test_sqlite_advanced/`），每个子目录独立 `main.fmf` + `test.sh`。粒度细，失败定位精准。
