# 软件包自动化测试脚本编写指南

基于 acl 软件包测试脚本的编写经验，总结以下规范和方法论。

## 一、测试脚本结构规范

### 1.1 基本结构

```bash
#!/bin/sh -eux
# 功能测试: [软件包名称] 软件包
# 测试 [软件包] 提供的 [命令列表] 命令功能
# 版本: [软件包版本]

# 1. 检查软件包安装
# 2. 获取版本信息
# 3. 创建测试环境
# 4. 分类测试各项功能
# 5. 错误处理测试
# 6. 特殊场景测试
# 7. 清理测试环境
```

### 1.2 元数据配置 (main.fmf)

```yaml
summary: 功能测试 - [软件包名称] 软件包功能验证
test: ./test.sh
tag:
  - functional
  - [软件包名称]
duration: [预估时间，如 5m]
tier: 1
require:
  - [软件包名称]
  - [其他依赖]
```

## 二、测试内容覆盖要求

### 2.1 必须覆盖的测试维度

1. **软件包安装验证**
   - 检查软件包是否已安装 (rpm -q)
   - 检查命令是否可用 (which)
   - 获取版本信息 (--version)

2. **核心命令基本功能**
   - 每个命令的基本使用
   - 常用参数测试
   - 帮助信息查看

3. **命令参数完整覆盖**
   - 所有主要参数至少测试一次
   - 参数组合使用
   - 互斥参数测试

4. **高级功能**
   - 批量操作
   - 递归操作
   - 从文件读取配置
   - 导入导出功能

5. **权限和继承**
   - 权限设置和验证
   - 继承机制测试
   - 默认值测试

6. **错误处理**
   - 无效参数
   - 不存在的文件/资源
   - 权限不足
   - 格式错误

7. **特殊场景**
   - 多用户/多组
   - 符号链接处理
   - 测试模式 (--test)
   - 边界条件

### 2.2 测试用例组织

```bash
echo "=== 测试 N: [测试类别] ==="

# 测试 N.1: [具体测试项]
[命令] [参数]
[验证命令]

# 测试 N.2: [具体测试项]
[命令] [参数]
[验证命令]
```

## 三、信息收集方法

### 3.1 软件包信息收集

在服务器上执行以下命令收集软件包信息：

```bash
# 1. 查看软件包信息
rpm -qi [软件包名称]

# 2. 查看软件包文件列表
rpm -ql [软件包名称]

# 3. 查看提供的命令
which [命令1] [命令2] [命令3]

# 4. 查看命令帮助
[命令] --help
[命令] -h

# 5. 查看手册页
man [命令]

# 6. 查看文档文件
ls /usr/share/doc/[软件包名称]/
cat /usr/share/doc/[软件包名称]/*.txt

# 7. 实际测试命令功能
cd /tmp
mkdir test_[软件包]
cd test_[软件包]
# 进行各种命令测试
```

### 3.2 命令参数分类

将命令参数按功能分类：

1. **查询类参数**: 用于查看信息（如 -l, --list, --version）
2. **修改类参数**: 用于修改配置（如 -m, --modify, --set）
3. **删除类参数**: 用于删除配置（如 -x, --remove, -b）
4. **控制类参数**: 控制行为（如 -R, -n, --test）
5. **输出类参数**: 控制输出格式（如 -v, -q, --numeric）

## 四、测试脚本编写流程

### 4.1 标准流程

1. **信息收集阶段**
   - 在服务器上安装软件包
   - 收集软件包和命令信息
   - 了解命令的所有参数和功能

2. **功能验证阶段**
   - 在服务器上手动测试各个命令
   - 验证命令的预期行为
   - 记录命令的输出和返回值

3. **脚本编写阶段**
   - 按照测试维度组织测试用例
   - 编写完整的测试脚本
   - 添加详细的注释说明

4. **验证测试阶段**
   - 在服务器上运行测试脚本
   - 修复发现的问题
   - 确认所有测试通过

5. **提交阶段**
   - 更新元数据文件
   - 提交到版本控制
   - 创建 MR 进行代码审查

### 4.2 质量检查清单

- [ ] 软件包安装检查
- [ ] 所有命令版本信息输出
- [ ] 基本功能测试覆盖
- [ ] 所有主要参数测试
- [ ] 高级功能测试
- [ ] 错误处理测试
- [ ] 边界条件测试
- [ ] 测试环境清理
- [ ] 元数据正确配置
- [ ] 脚本语法正确
- [ ] 在目标平台验证通过

## 五、常用测试模式

### 5.1 设置-验证模式

```bash
# 设置
[命令] [设置参数] [目标]

# 验证
[查询命令] [目标]
```

### 5.2 错误测试模式

```bash
# 预期失败的命令
[命令] [错误参数] || echo "Expected error"
```

### 5.3 清理模式

```bash
# 记录测试目录
TmpDir=$(mktemp -d)
cd $TmpDir

# ... 执行测试 ...

# 清理
cd /
rm -rf $TmpDir
```

## 六、注意事项

### 6.1 脚本编写注意

1. 使用 `#!/bin/sh -eux` 作为 shebang
   - `-e`: 遇到错误立即退出
   - `-u`: 使用未定义变量时报错
   - `-x`: 显示执行的命令

2. 所有测试都要有清晰的输出信息
3. 测试环境必须在使用后清理
4. 使用相对路径而非绝对路径
5. 避免硬编码用户/组名，使用系统存在的

### 6.2 服务器测试注意

1. 在 /tmp 目录下创建测试环境
2. 使用 mktemp 创建临时目录
3. 测试完成后必须清理
4. 避免修改系统关键文件
5. 使用 root 权限时注意安全性

### 6.3 跨平台兼容

1. 考虑不同架构的差异（x86_64, aarch64, riscv64）
2. 考虑不同发行版的差异
3. 命令路径可能不同（使用 which 定位）
4. 某些参数在不同版本可能不支持
